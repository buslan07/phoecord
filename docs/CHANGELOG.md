## [Unreleased]

### Added

- 2.3.2: two more built-in themes, `themes/light.toml` and `themes/high-contrast.toml` (every text colour at least 7:1), and `phoecord theme import <vencord-theme.css>`, which turns a Vencord theme's colour variables into a `theme.toml` and lists what does not carry over. Theme authoring: `docs/plugins/themes.md`. The palette field names are still PhoeCord's own until Phoenix's are known.
- 2.4.2 (a): message sends and edits with files (`multipart/form-data`) reach plugins: they see `payload_json` as the body, and a change is written back with the same boundary, file names following `attachments[].filename`; file bytes are passed as they are. So ClearURLs, FakeNitro, TextReplace and the other send plugins now also work on messages with attachments. Bodies over 64 MiB stream through unread.
- 2.4.2 (b): `/phoecord serverinfo` also lists your friends, blocked and ignored users who are in that server, like Vencord's tabs: one gateway op 8 per lookup with the ids from `READY` / `RELATIONSHIP_*` (at most 100), answered by a local message when the last `GUILD_MEMBERS_CHUNK` with PhoeCord's nonce is in; those chunks never reach the client.
- 2.2.6: `scripts/check_builds.py <folder>` runs `phoecord check` on every client exe in a folder outside the repository and fails when one does not pass; `--phoenix` requires the `DiscordPhoenix` path that makes locator misses fail, `--min-builds 2` asks for two builds. No CI job runs it yet.
- 2.2.6 (second part): `phoecord check` also runs the typed locators of the hook targets (`http_send`, the allocator, the gateway registry) and prints what each found and how; for a Phoenix exe a locator miss fails the check.
- 2.4.2 (c): MusicRichPresence reaches a self-hosted ListenBrainz-compatible instance: `listenbrainzHost` names it and `fetch_hosts` in the same `[plugins.music_rich_presence]` section allows it. `fetch_hosts` works for any plugin: exact host names the user adds to that plugin's `fetch` list in `config.toml` (a plugin cannot write it).
- 2.4.2 (d): message context menu entries for UnsuppressEmbeds (`toggle_embeds`), ViewRaw (`view_raw`) and SilentDelete (`silent_delete`, `silent_delete_history`) against the frozen API; a click does what the `/phoecord` command does and answers with a local message only the user sees (`commands::local_message`). They show on Phoenix once 2.3.5 hooks the menu.
- 2.1.10 (partial, was 1.1.9): `scripts/scrub_fixture.py` rewrites a decoded Gateway event into a fixture with no real data — every key, the nesting and each value's JSON type are kept, every string and every snowflake-shaped value (string or integer, keys included) is replaced with an invented one, and the Gateway envelope (`op`/`t`/`s`) and Discord's own `type` enums are left alone so a fixture stays loadable by event name; a shared `--map` file keeps a repeated id consistent across several fixtures from the same capture. `tests/fixtures/README.md` documents the capture-then-scrub workflow. The fixtures themselves are not recorded yet: that step needs a human with a throwaway account and a running client.

- 2.4.2 (e): plugin settings are described for the settings tab. Plugin API v1 gets `Manifest.settings` (`SettingSpec { key, kind, default, options, label }`, `SettingKind`: bool, number, text, choice, list; additive), WASM packages declare `[[setting]]` in `plugin.toml` (checked: kind, default fitting the kind, a choice's options, no duplicates), and 40 built-in plugins carry 143 specs with English and Russian labels.
- 2.3.1 / 2.3.4 (partial, not wired to a real Phoenix hook): `themes/default.toml` ships a starting-point theme with Discord's own published surface colours (field names are placeholders, not yet Phoenix's real palette fields — unknown, see 2.3.1's status); `phoecord_loader::ui::message_logger::Accessory::for_message` decides what a `MessageRow::render` wrap would show for a logged message (deleted, or edited with its history), pure and tested. - 2.4.5: PhoeCord installs on all three systems from a release file and keeps itself up to date. Linux gets a `.deb` (Debian, Ubuntu, Mint) and an `.rpm` (Fedora, openSUSE) with the installer window, `phoecord` and a menu entry. The Windows setup now carries the loader (in `loader\version.dll`, never next to `phoecord.exe`), stops PhoeCord's proxy before it replaces files, and removing PhoeCord in Installed apps undoes setup first: CA trust, autostart, shortcuts, loader copies. **Automatic updates:** once a day an installed copy looks at this repository's GitHub Releases, downloads the installer for this system and installs it the next time the window or the background proxy starts, only when its SHA-256 matches the release's `SHA256SUMS` (drafts and prereleases are skipped; anything missing or different is refused). All or nothing per launch: with every network hook found Phoenix runs in-process and no proxy process is started at all; with any one missing the whole launch goes through the proxy and the loader does the UI only. A build the loader marks failed goes to the proxy until the signatures change. `--transport auto|proxy|in-process` and `[phoenix] transport = "auto"` in `config.toml` override the choice; macOS and Linux get the proxy and a plain launch. Today no build can run in-process yet (the gateway send hook, 2.2.4, and the in-process transport wiring, 2.2.7, are not there), so `auto` chooses the proxy and says why. The Phoenix shortcut is now "Discord Phoenix (PhoeCord)"; `uninstall` also removes the check cache.

- 2.2.5 (first part): the typed locator framework in `phoecord_loader::locators`. ### Changed

- 2.4.5: Windows has one installer, the setup `.exe`; the `.msi` is no longer built (a setup run over a 0.5 `.msi` install offers to remove it). Releases are published only after every file is uploaded.
- macOS: the minimum is now macOS 13 (Ventura), because the client is started with `open --env`, which macOS 13 added. Macs on macOS 11 and 12 cannot install 0.5.1.
- `Host::emit_send` from a REST event (for example a `/phoecord` command) or a timer goes to the live gateway connection at once instead of being lost; every plugin-queued send passes the Send chain once.
- The per-plugin `Host::rest` limit allows bursts: 5 calls per 5 s (was 1 per second); a refusal says `retry in X s`. The 5/s overall cap and Discord's buckets are unchanged.
- 1.5.8: the loader (`version.dll`) is cheap: Electron child processes (`--type=` on the command line) get export forwarding only, no worker, and the main process identifies the client build from the exe already mapped in memory instead of reading the whole file (about 140 ms and 224 MB per process before); the log line `client build: …` now ends with the detection time in ms. The `.text` hash is unchanged, so existing `signatures/*.toml` keep matching.

### Fixed

- `/phoecord petpet`, `serverinfo`, `viewraw`, the Spotify share commands and `tags` / `tag` always answered "did not run": PetPet, ServerInfo, ViewRaw, SpotifyShareCommands and CustomCommands were built but never put in the plugin chain, where their answers are computed. A test now checks every plugin behind a `kept_answer` command.
- Twelve data parts from 1.2.16 (MemberCount, MessageLinkEmbeds, ReadAllNotificationsButton, PauseInvitesForever, PlatformIndicators, UserVoiceShow, TypingIndicator, VcNarrator, NewGuildSettings, ValidReply, ValidUser, OverrideForumDefaults) read gateway dispatches as bare data while the proxy hands plugins the whole `{op, t, d}` frame, so they saw nothing in a real session; they now read `d` through `state::dispatch_data`, with a real-frame test each.
- macOS: Discord started by PhoeCord could not read its own data ("Operation not permitted", `installer.db` could not be opened, the updater showed "Installation paused"), because as a child of PhoeCord.app it was treated as PhoeCord.app reaching into another app's data. A `.app` client is now started through LaunchServices (`open -n -a <Discord>.app --env ... --args --proxy-server=...`), so it is its own process. Windows and Linux are unchanged.
- macOS: the downloaded `PhoeCord.app` said "damaged and can't be opened". The app is now ad-hoc signed after packaging and the `.dmg` is refreshed with the signed copy (`scripts/package/sign-macos.sh`); the installers job checks the signature with `codesign --verify`. macOS now shows the ordinary "unidentified developer" prompt with Open Anyway.
- Release notes start with "Which file do I download?" and the macOS note has the `xattr -dr com.apple.quarantine` fallback.
- `phoecord` with no command no longer silently starts the proxy: it prints what PhoeCord is and the main commands (English and Russian) and exits. Autostart (launchd, systemd, Run key), shortcuts and the installer window already pass `run` or `launch`, so entries written by 0.5.0 keep working without a rewrite.
